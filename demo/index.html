Family photo archive · project walkthrough

Every original safe in S3.
Every photo searchable from your Mac, iPhone and Android.

Photoframing moves originals out of Apple Photos into cheap cold storage. It keeps a small copy of each photo with all its metadata, builds a SQLite catalog, and gives you one website to search it from any device, even offline.

What it does

Features

Grouped by what you get. The status shows what already runs today and which milestone in docs/TASKS.md delivers the rest.

Archive from Apple Photos

Built
  • Pick what to archive: what's selected in Photos, an album, a date range, or everything
  • Originals go to S3 Deep Archive, checked by SHA-256
  • Works with photos, RAW pairs, Live Photo videos and videos
  • Re-runs skip anything already archived
  • Archived items go to an "Archived to S3" album in Photos for review
M0 · photoctl archive

Small copies, full metadata

Built
  • 1600px JPEG per photo via macOS sips, with EXIF and GPS kept
  • 720p MP4 plus a poster frame per video via ffmpeg
  • JSON sidecar with Apple people, albums, keywords, place and labels
  • The same ID links original, copy and sidecar
  • --local-only mode to test compression without uploading
M0 · derive.py

Safe, cheap storage

Built
  • Private bucket, encrypted, versioned, HTTPS only
  • Lifecycle rules move copies to cheaper storage after 30 days
  • Upload-only IAM policy with no delete permission
  • Terraform in infra/, with a guard against deleting the bucket

    How it fits together

    Architecture

    The Mac does the heavy work and holds the AWS credentials. S3 is the source of truth. Phones reach the Mac over Tailscale, or work offline from a downloaded catalog.

    Mac

    • Reads Apple Photos, compresses, uploads
    • Holds AWS credentials (SSO or aws login)
    • Runs the API, web UI and sync loop
    • Local locks stop two archive runs at once

    S3 (source of truth)

    • Originals and copies share one content-based ID
    • Changes are append-only operation files, one folder per device
    • Conditional writes (If-None-Match, If-Match) act as locks
    • Database backups under backups/; any device can be recovered from here

    Phones

    • Same UI in Safari and Chrome, installable
    • SQLite in the browser for offline search
    • Push and pull changes through the Mac's API
    • Native app backs up the camera roll on every sync

    Tech stack

    • CLI: Python 3.12, uv, click, osxphotos, boto3
    • Media: macOS sips (photos), ffmpeg (videos)
    • Data: SQLite WAL + FTS5; sqlite-wasm on phones
    • API: FastAPI, tus resumable uploads, SSE progress
    • UI: React + Vite + TypeScript, installable PWA
    • Infra: S3 + IAM via Terraform / OpenTofu
    • Access: Tailscale (private HTTPS)

    Before we start

    Roadmap and open decisions

    Each milestone is a checklist in docs/TASKS.md, and every task has a "done when" check. We tick them off as we go.

    D1 · UI stack

    React + Vite + TypeScript. Recommended, and needed for on-device search.

    D2 · Remote access

    Tailscale. Recommended: free, private, real HTTPS on iOS and Android.

    D3 · Phone upload fidelity

    Accept browser limits for now and flag missing GPS. A native app later gives full metadata.

    D4 · Offline images

    Thumbnails by default, with opt-in "Save offline" for compressed copies.

    D5 · When changes sync

    At the end of each run, and every 60 seconds for edits.

    D6 · Deleting

    "Remove from library" only hides an item. Purging originals stays an admin-only command.

    D7 · DB backup schedule

    After every archive run and daily. Keep 30 daily and 12 monthly backups.

    D8 · Phone backup defaults

    Wi-Fi only, videos only while charging, screenshots skipped.
